# Template Base 🐼

Сучасний шаблон на React для створення інтерактивної документації та баз знань на основі Markdown. Він містить готовий інтерфейс із навігацією, пошуком, перемиканням теми, адаптивною версткою, підтримкою зворотного зв'язку та налаштованими блоками контенту, що дозволяє зосередитися на наповненні, а не на створенні інтерфейсу документації з нуля.

## Можливості

* **Контент на основі Markdown**: Документація створюється за допомогою стандартного Markdown із підтримкою GitHub Flavored Markdown.
* **Структурована навігація**: Автоматично створює дерево навігації на основі заголовків Markdown.
* **Потужний пошук**: Пошук по всій документації з підсвічуванням збігів та навігацією між результатами.
* **Адаптивний інтерфейс**: Інтерфейс документації адаптується до настільних, планшетних та мобільних екранів.
* **Темна тема**: Підтримує світлу, темну та системну тему зі збереженням вибраної настройки локально.
* **Кастомні колонки контенту**: Підтримує `cols-2`, `cols-3` та інші налаштовані Markdown-сітки для організації інформації у картки та колонки.
* **Зворотний зв'язок через виділення тексту**: Виділіть будь-який текст та натисніть `Ctrl + Enter` / `Cmd + Enter`, щоб надіслати його як відгук.
* **Feedback API**: Містить безсерверний API endpoint для отримання відгуків користувачів.
* **Налаштування**: Має інтерфейс налаштувань для керування темою та автоматичним виділенням тексту.
* **Анімація завантаження**: Відображає легку анімацію завантаження під час підготовки Markdown-контенту.
* **Сучасна архітектура React**: Побудований на React 19, React Compiler, Vite та сучасному frontend-інструментарії.
* **Tailwind CSS**: Використовує Tailwind CSS v4 для стилізації та адаптивної верстки.
* **Легка кастомізація**: Шаблон можна адаптувати під бази знань, документацію підтримки, внутрішні інструкції, FAQ та інший структурований контент.

## Початок роботи

### Вимоги

* Встановлені Node.js та npm.
* Базові знання React та Markdown.
* Сучасний браузер із підтримкою JavaScript.

### Встановлення

1. Клонуйте репозиторій:

   ```bash
   git clone https://github.com/Niarosss/template-base.git
   ```

2. Перейдіть до каталогу проєкту:

   ```bash
   cd template-base
   ```

3. Встановіть залежності:

   ```bash
   pnpm install
   ```

### Розробка

Запустіть локальний сервер розробки:

```bash
pnpm dev
```

Застосунок буде доступний за локальною Vite-адресою, яку буде показано в терміналі.

### Production-збірка

Створіть оптимізовану production-збірку:

```bash
pnpm build
```

Для локального перегляду production-версії:

```bash
pnpm preview
```

### Перевірка ESLint

Запустіть ESLint для перевірки проєкту:

```bash
pnpm lint
```

## Налаштування контенту

Контент документації наразі задається через елемент `<x-md>` у `index.html`.

Шаблон підтримує спеціальні Markdown-секції для визначення глобального контенту:

```md
::: greeting
Вітаю! Дякуємо за звернення до нашої служби підтримки.
::: signature
З повагою,
Служба підтримки
:::
```

Ці значення можуть використовуватися шаблоном під час відображення блоків контенту.

### Багатоколонковий макет

Контент можна групувати у responsive-колонки за допомогою спеціальних блоків `cols-*`:

```md
::: cols-3
## ОБЛІКОВИЙ ЗАПИС

Інформація про обліковий запис.

## БЕЗПЕКА

Інформація про безпеку.

## ОПЛАТА

Інформація про оплату.
:::
```

Шаблон автоматично перетворює такі блоки на адаптивні grid-макети.

### Підтримка Markdown

Рендерер підтримує стандартний Markdown разом із можливостями GitHub Flavored Markdown:

- Таблиці
- Списки завдань
- Закреслений текст
- Посилання
- Списки
- Блоки коду
- Raw HTML

### Гарячі клавіші

| Комбінація                     | Дія                                 |
| ------------------------------ | ----------------------------------- |
| `Ctrl + F` / `Cmd + F`         | Відкрити пошук документації         |
| `Ctrl + K` / `Cmd + K`         | Відкрити пошук документації         |
| `/`                            | Відкрити пошук документації         |
| `F3`                           | Наступний результат пошуку          |
| `Shift + F3`                   | Попередній результат пошуку         |
| `Ctrl + Enter` / `Cmd + Enter` | Надіслати виділений текст як відгук |

### Feedback API

Проєкт містить безсерверний endpoint для роботи зі зворотним зв'язком:

```
api/feedback.js
```

Користувач може виділити частину документації та надіслати її як відгук за допомогою `Ctrl + Enter` або `Cmd + Enter`.

Це дозволяє створювати систему документації, у якій користувачі можуть безпосередньо повідомляти про неправильну, незрозумілу або застарілу інформацію.

### Структура проєкту

```
template-base/
├── 📁 api/                       # Безсерверні API endpoints
│   └── 📄 feedback.js            # API для зворотного зв'язку
├── 📁 src/                       # Вихідний код застосунку
│   ├── 📁 components/            # UI-компоненти
│   ├── 📁 context/               # React-контексти
│   ├── 📁 utils/                 # Допоміжні функції
│   ├── 📄 App.jsx                # Головний компонент застосунку
│   ├── 📄 index.css              # Глобальні стилі
│   └── 📄 main.jsx               # Точка входу застосунку
├── 📄 index.html                 # HTML-точка входу та контент документації
├── 📄 eslint.config.js           # Конфігурація ESLint
├── 📄 package.json               # Залежності та скрипти проєкту
├── 📄 pnpm-lock.yaml             # Lock-файл залежностей
└── 📄 vite.config.js             # Конфігурація Vite
```

### Кастомізація

Шаблон спеціально організований так, щоб інтерфейс застосунку та контент документації можна було змінювати незалежно один від одного.

Можна налаштувати:

- Контент документації
- Структуру навігації
- Header та Sidebar
- Пошук
- Теми
- Рендеринг Markdown
- Колонкові макети
- Обробку зворотного зв'язку
- Анімацію завантаження
- Footer
- UI-компоненти та стилі

Основний контент документації можна змінити безпосередньо в `index.html`, тоді як інтерфейс застосунку організований у `src/`.

### Розгортання

Проєкт можна розгорнути на будь-якій платформі, що підтримує статичні Vite-застосунки.

#### Vercel

1. Запуште проєкт у Git-репозиторій.
2. Імпортуйте репозиторій у Vercel.
3. Вкажіть команду збірки:
    ```
    pnpm build
    ```
4. Вкажіть директорію результату:
    ```
    dist
    ```
5. Розгорніть проєкт.

Готову production-збірку також можна розмістити на GitHub Pages, Netlify, Cloudflare Pages або іншому сервісі статичного хостингу.
